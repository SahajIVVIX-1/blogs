Paper summary: A.S.E: A Repository-Level Benchmark for Evaluating Security in AI-Generated Code

A.S.E is a repository-level benchmark for the security of AI-generated code; it finds that current LLMs still struggle with secure coding, and that a bigger reasoning budget doesn't reliably help.

Paper card
Paper
A.S.E: A Repository-Level Benchmark for Evaluating Security in AI-Generated Code (2025)
Authors
Keke Lian, Bin Wang, Lei Zhang, Libo Chen, Junjie Wang, Ziming Zhao et al.
Task
Evaluating the security of AI-generated code in realistic settings
Method
Repository-level benchmark mirroring real AI-assisted programming tasks
Data
A.S.E tasks built from real repositories
Result
Leading LLMs still struggle with secure coding; repository context is harder than snippets; more reasoning budget isn't reliably better, per the abstract
Links
arXiv · PDF · code

Problem

LLMs write more and more production code, but existing security benchmarks often test isolated snippets that don’t reflect real AI-assisted programming.

Method

A.S.E (AI Code Generation Security Evaluation) is a repository-level benchmark. Tasks mirror real programming work inside actual codebases, giving a more realistic test of whether generated code introduces security problems.

Key results

From the abstract, evaluating leading LLMs:

  • current LLMs still struggle with secure coding
  • repository-level complexity is hard even for models that do well on snippet-level tasks
  • a larger reasoning budget does not necessarily lead to better code

Limitations

There’s no dedicated limitations section in the extracted text. Results reflect the models available when the benchmark was built.
